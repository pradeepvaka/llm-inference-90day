02 — STATE

The KV cache is the model’s working set

Causal decoding would repeatedly recompute keys and values for every prior token without caching. The cache trades that compute for persistent device memory.

KV bytes = B · L · S · 2 · Hkv · dh · p

B batch · L layers · S cached tokens · 2 for keys and values · Hkv KV heads · dh head dimension · p bytes per element.

Growth is linear

Each new token contributes one K vector and one V vector in every layer.

cached tokennew append
!

GQA changes the coefficient, not the growth law. Sharing K/V heads makes each token cheaper, but memory still grows linearly with sequence count, context length, and layers.

03 — ATTENTION

Count work from tensor shapes

Big-O hides the constants that determine deployment. Start with Q, K, V shapes and count multiply-adds and bytes moved.

PREFILL / ONE LAYER

All queries see a causal prefix

QKᵀ + PV ≈ 4 · S² · D FLOPs

For Hq query heads of width dh, D = Hqdh. The triangular causal mask roughly halves valid score pairs, but kernels and counting conventions vary—state your assumption.

DECODE / ONE LAYER / ONE TOKEN

One query scans the history

QKᵀ + PV ≈ 4 · S · D FLOPs

The step is linear in current context length S. Across an N-token generation, the summed attention work grows with the area under that line: roughly proportional to N·Sprompt + N²/2.

≠

Compute complexity is not memory allocation. FlashAttention avoids materializing the full S×S score matrix in HBM, but it does not remove the attention FLOPs. KV cache allocation stays O(S); attention work in prefill stays O(S²).

decode KV bytes read ≈ 2 · S · Hkv · dh · p per layer, per sequence, per step

Kernel implementations, cache layout, quantization metadata, and data reuse change realized traffic. This is a first-order lower-bound-style model, not a profiler replacement.

04 — ROOFLINE

Arithmetic intensity predicts the bottleneck

Arithmetic intensity (AI) is useful work per byte moved from the limiting memory level. Compare it with the hardware’s compute-to-bandwidth ratio.

AI = FLOPs / bytes   ·   attainable FLOP/s ≤ min(peak compute, AI × bandwidth)

GQA can lift AI

AI ≈ 2Hq / (Hkvp)

Using attention FLOPs 4SHqdh and KV bytes 2SHkvdhp. With 32 query heads, 8 KV heads, and 2-byte values: ≈4 FLOP/byte before other traffic.

WEIGHT STREAMING ESTIMATE

Batching creates reuse

AIlinear ≈ 2B / p

If a weight is fetched once and reused across B independent token rows, effective AI rises with batch. Real kernels also move activations and may not achieve perfect reuse.

→

Optimization follows the regime. Compute-bound prefill rewards efficient tensor-core GEMMs and tiling. Bandwidth-bound decode rewards weight/KV quantization, larger effective batches, cache locality, and fewer bytes per token.

Find the knee
