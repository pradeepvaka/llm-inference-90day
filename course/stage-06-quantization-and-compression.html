Precision is a systems knob.

FP8, INT8, AWQ, GPTQ, and sparsity are not interchangeable “compression settings.” Each moves a different bottleneck—and each fails in a different way. Learn to choose by workload, kernel path, and measured quality loss.

00 / OPERATING FRAME

Start with the bottleneck

Quantization pays when it removes the resource limiting your phase of inference. The same checkpoint can help decode, do little for prefill, or even regress if its kernel path adds unpacking overhead.

Decode

Usually weight-bandwidth constrained at small batches. Weight-only INT4 often shines because fewer bytes cross HBM per token.

Prefill

More compute-dense. W8A8 or FP8 can exploit native low-precision matrix units when shapes and kernels align.

Long context

KV cache can dominate capacity and traffic. Weight compression alone does not shrink the cache.

!
The prime directiveNever claim “4× smaller means 4× faster.” File size, resident memory, HBM traffic, arithmetic throughput, launch overhead, and end-to-end latency are different quantities.

01 / MECHANICS

Quantization is a mapping

An affine integer quantizer stores a small integer q plus metadata. Dequantization reconstructs an approximation, not the original value.

q = clamp(round(x / s) + z, qmin, qmax)
x̂ = s · (q − z)
s = scale · z = zero point · x̂ = reconstructed value

Granularity controls error

Per-tensor uses one scale. Per-channel gives each output channel a scale. Per-group shares a scale across a small block of weights. Finer granularity usually lowers error but increases metadata and kernel complexity.

Clipping controls range

A scale wide enough for outliers wastes levels on the dense center. A tighter scale resolves common values but clips tails. Calibration chooses that compromise.

02 / NUMERIC FORMATS

FP8 and INT8 spend bits differently

INT8 buys uniform precision inside a calibrated interval. FP8 buys logarithmic dynamic range through an exponent. Both occupy one byte; their error surfaces and hardware paths differ.

INT8

  • Uniform step after scaling
  • Usually explicit scale; optional zero point
  • Outliers stretch the interval

FP8 E4M3

  • More significand precision
  • Smaller range than E5M2
  • Common for forward tensors

FP8 E5M2

  • Wider dynamic range
  • Fewer significand bits
  • Often useful where range matters

03 / WEIGHT-ONLY INT4

AWQ protects salience. GPTQ compensates error.

Both typically produce low-bit weight-only models, often W4A16. They differ in how they decide what quantization error is acceptable.

AWQ

Activation-aware scaling

Calibration activations reveal salient channels. An equivalent scaling transformation makes important weight channels easier to quantize, without mixed-precision storage or backpropagation.

GPTQ

Second-order compensation

Layers are quantized sequentially using approximate Hessian information. As columns are rounded, later weights are updated to compensate for induced output error.

04 / SPARSITY

Zeros matter only when hardware can skip them

Unstructured pruning may compress a file yet lose to dense kernels. Structured patterns trade freedom for predictable acceleration. NVIDIA’s 2:4 pattern keeps two nonzero values in each contiguous group of four supported elements.

Dense

→

2:4 structured

Unstructured

Any element may be zero. Highest pruning freedom; usually needs specialized sparse kernels and metadata.

N:M structured

Exactly N nonzeros per M-element group. Constrained enough for hardware to exploit predictably.

Block sparse

Entire tiles are zero. Coarser but easier to map to matrix kernels and memory transactions.

×
Compression methods can interfereQuantization changes weight error; pruning removes weights. Applying both independently may compound quality loss, and the resulting quantized-sparse layout still needs a fused kernel to realize a speedup.
05 / DECISION MAP

Choose the candidate, not the winner

These are starting hypotheses. Your model, prompt distribution, batch scheduler, and accelerator decide the final choice.

SMALL-BATCH DECODE

HIGH-THROUGHPUT PREFILL

06 / MEASUREMENT

Build a Pareto frontier

A compressed model ships only when it is nondominated: no alternative is both higher quality and faster (or cheaper) under the same workload.

Freeze the workload

Pin model revision, tokenizer, engine, GPU clocks, request traces, prompt/output lengths, batch policy, and sampling settings. Record warmup separately.

Measure four systems axes

Peak resident memory, time to first token (TTFT), inter-token latency (ITL), and throughput at target concurrency. Report median plus p95/p99—not only averages.

Use layered quality gates

Start with perplexity or token-level divergence, then task benchmarks, then adversarial slices: long context, code, math, rare languages, JSON constraints, and refusal behavior.

Attribute the gain

Profile kernel names, achieved bandwidth, tensor-core utilization, conversion kernels, and scheduler idle time. Prove the intended low-precision kernel executed.

Repeat and bound variance

Run enough repetitions to distinguish a real change from noise. Keep the same prompt order or random seed; report error bars where variance matters.

07 / HANDS-ON LAB

Quantize, benchmark, defend

The lab has two layers: a zero-dependency numerical experiment, then a real serving benchmark using your engine’s supported checkpoints. The deliverable is a one-page decision memo—not a screenshot of a smaller file.

Lab contractBASELINE + 2 CANDIDATES · SAME TRACE · 3 QUALITY SLICES

A. Run a local quantization microscope

This script demonstrates symmetric per-tensor versus per-row INT8 and prints reconstruction error. Replace the random matrix with captured weights or activations only if your data policy allows it.

quant_microscope.py
import numpy as np

rng = np.random.default_rng(7)
x = rng.normal(0, 0.35, (64, 256)).astype(np.float32)
x[:, 17] *= 12  # activation-like outlier channel

def sym_int8(a, axis=None):
    maxabs = np.max(np.abs(a), axis=axis, keepdims=True)
    scale = np.maximum(maxabs / 127.0, 1e-12)
    q = np.clip(np.rint(a / scale), -127, 127).astype(np.int8)
    return q, scale, q.astype(np.float32) * scale

_, s_tensor, x_tensor = sym_int8(x)
_, s_row, x_row = sym_int8(x, axis=1)

for name, recon, scales in [
    ("per_tensor", x_tensor, s_tensor),
    ("per_row", x_row, s_row),
]:
    mse = np.mean((x - recon) ** 2)
    maxerr = np.max(np.abs(x - recon))
    print(f"{name:>10}  mse={mse:.8f}  maxerr={maxerr:.6f}  scales={scales.size}")

C. Inspect the serving path

Use the engine’s current documentation to select supported model files and commands. Capture the engine version, quantization metadata, loaded kernel path, and any fallback warnings. Then profile one representative run.

Required evidence

Engine log showing detected quantizer; profiler trace with low-precision GEMM; peak allocation; exact prompt-length histogram; benchmark command and commit.

Stop conditions

Fallback to generic GEMM; conversion cost dominates; benchmark spills to CPU; tokenizer mismatch; quality evaluation silently truncates long prompts.

08 / KNOWLEDGE CHECKS

Can you defend the choice?

Answer before opening the explanation. A production decision is complete only when you can explain the mechanism and the failure case.

At low-batch decode, each token can require streaming much of the weight set, so cutting weight bytes attacks the bandwidth bottleneck. Prefill has higher arithmetic intensity and may be compute-bound; W4A16 still computes with high-precision activations and pays unpack/dequantization cost, so it may not exploit the same low-precision compute throughput as W8A8 or FP8.
Finer groups fit local distributions better, lowering quantization error. But they require more scales/zero points, more metadata loads, and more frequent scaling inside the kernel. They can also mismatch the kernel’s preferred tile layout.
It does not prove instruction following, tool-use correctness, long-context retrieval, structured-output validity, calibration of confidence, multilingual behavior, safety behavior, or production latency. It is a sensitive early signal, not a release verdict.
When the pattern is unsupported, the sparse metadata/indirection outweighs saved work, the implementation densifies before GEMM, the layer is not dominant, or another bottleneck—memory, attention, scheduler, CPU—limits end-to-end latency.
