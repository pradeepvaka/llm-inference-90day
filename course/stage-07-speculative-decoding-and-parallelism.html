Speculative decoding & parallelism

Two ways to attack inference latency: predict several tokens before the large model verifies them, and divide the model’s work across accelerators without letting communication erase the gain.

01 / THE BOTTLENECK

Decode is a serial dependency chain

Autoregressive generation creates one token, appends it to the sequence, then uses that token to create the next. Prefill can process prompt tokens in parallel; decode cannot remove the dependency between successive outputs. On a single request, the GPU often reads the model weights for every generated token while performing comparatively little arithmetic.

TTFT

Time to first token

Dominated by prompt prefill, queuing, and scheduling. Tensor or pipeline parallelism can reduce compute time for a large prompt, but communication and bubbles matter.

TPOT

Time per output token

Dominated by repeated decode steps. Speculation tries to retire multiple tokens per expensive target-model invocation.

effective output rate ≈ accepted tokens per verification ÷ verification-step time
Core distinctionParallelism makes one model step finish sooner or serve more work at once. Speculation reduces how many target-model steps are needed for a sequence. They attack different terms and can be composed.
02 / DRAFT–TARGET SPECULATION

Let a cheap model guess; let the target verify once

A small draft model proposes a block of k tokens. The target model evaluates that proposed continuation in one teacher-forced pass, producing distributions for all draft positions. A rejection-sampling rule accepts a prefix without changing the target model’s output distribution; when a token is rejected, generation samples from a corrected residual distribution.

The target’s extra distribution at position k+1 lets a fully accepted block emit one additional target-sampled token.

Acceptance is probability-correct, not “agree or discard”

Let the draft assign probability q(x) and target assign p(x) to the proposed token x. Accept the draft token with probability:

A(x) = min(1, p(x) / q(x))

If rejected, sample from the normalized positive residual max(0, p − q). This construction preserves the target distribution exactly, assuming both distributions and random sampling are implemented correctly. A greedy variant can simply accept matching argmax tokens, but it preserves greedy output rather than the full sampling distribution.

03 / MEDUSA-STYLE HEADS

Predict futures from the target’s own hidden state

Medusa attaches multiple lightweight decoding heads to a frozen or adapted base model. Head 1 predicts the next token, head 2 predicts two steps ahead, and so on. Their top candidates form a tree of possible continuations. A tree attention mask lets the base model verify multiple branches in one pass while preventing branches from attending to incompatible siblings.

Candidate breadth raises the chance of finding a good branch, but also expands verification tokens and attention bookkeeping.

Why it can be fast

No separate autoregressive draft-model loop. The extra heads are small, and candidates are predicted from an already-computed target hidden state.

Why it is not free

Heads require training and checkpoint changes. Candidate-tree size, tree-attention kernels, verification layout, and KV-cache commit logic all enter the critical path.

04 / MODEL PARALLELISM

Tensor parallel or pipeline parallel?

Once a model—or its target latency—outgrows one accelerator, the partition determines which communication lands on the critical path. Tensor parallelism splits arithmetic inside each layer. Pipeline parallelism splits groups of layers into stages.

Tensor parallelism

Each device owns a shard of layer weights. Matrix multiplications run concurrently, then collectives combine partial activations.

low stage bubble · frequent collectives

VS

Pipeline parallelism

Each device owns consecutive layers. Activations move point-to-point between stages; microbatches keep stages occupied.

less frequent links · pipeline bubbles

Tensor parallelism: communication every layer

Column- and row-parallel linear layers distribute the MLP and attention projections. A typical transformer block requires collective communication such as all-reduce or reduce-scatter/all-gather. Fast intra-node fabrics make this practical; slow inter-node links can dominate small decode steps.

T_layer ≈ max(T_compute / TP, T_memory / TP) + T_collective(message, topology)

Pipeline parallelism: bubbles and stage balance

A request flows through stage 0, then stage 1, and so on. With one decode token from one sequence, later stages wait while earlier stages work. Batching and microbatch interleaving improve utilization, but online decode’s dynamic sequence lengths and strict token dependencies complicate schedules.

idealized pipeline efficiency ≈ microbatches / (microbatches + stages − 1)

The formula is a teaching approximation for a balanced one-forward pipeline. Real inference also includes variable stage times, transfers, scheduler gaps, and autoregressive recurrence.

05 / COMPOSITION

Speculation changes the workload seen by parallelism

A verification step processes a short token block rather than a single decode token. That can increase arithmetic intensity and collective message size, making the target step friendlier to TP. But accepted lengths vary by request, so the scheduler receives irregular bursts instead of uniform one-token steps.

  • Place the draft deliberately. A draft on the same devices can compete for memory bandwidth. A draft on separate devices adds transfer and coordination. Benchmark both if the model is large enough to matter.
  • Separate proposal KV from committed KV. Only accepted target states become durable sequence state. Rejected branches must not leak into future attention.
  • Budget verification tokens. A large tree or long draft block consumes slots that could have served other requests. Admission control should reason in scheduled tokens, not just request count.
  • Adapt at runtime. Acceptance varies with temperature, task, language, model pair, and prompt phase. A controller can shorten or disable speculation when recent utility turns negative.
# Per-request controller sketch
utility_ema = accepted_tokens / max(1, proposed_tokens)

if queue_pressure > high_watermark:
    depth = min(depth, 2)          # protect batch capacity
elif utility_ema < 0.35:
    depth = max(0, depth - 1)      # poor draft alignment
elif target_step_is_underfilled:

07 / KNOWLEDGE CHECK

Can you defend the design?

Because the acceptance and residual-sampling rules transform samples from the draft proposal back into exact samples from the target distribution. “The models usually agree” is not enough; the correction step is what preserves distributional correctness.
Higher acceptance can be outweighed by more draft compute, more weight traffic, larger KV state, or device contention. Compare saved target steps against proposal and verification cost end to end.
TP typically invokes collectives at transformer-layer frequency. Latency and bandwidth of the fabric therefore enter every decode step. Intra-node links are usually much better suited to that pattern than cross-node networking.
A small number of active microbatches leaves stages idle, while variable sequence lengths and request arrivals make stage occupancy uneven. The theoretical partition can fit memory yet miss latency and utilization targets because of bubbles.
Verification schedules multiple candidate tokens for one sequence, consuming token budget in bursts. Rejections make committed work variable. Without a token-aware scheduler, speculative requests can reduce fairness or displace ordinary decode work.
08 / FIELD GUIDE

Deployment heuristics

Start baseline
Measure prefill and decode separately. If queueing dominates, model-step acceleration may not move user latency.
Try draft–target
Best when an aligned, much cheaper draft already exists and target weights should remain untouched.
Try Medusa
Best when you control training/checkpoints and can integrate tree verification into the serving runtime.
Choose TP
Favor fast fabrics, latency-sensitive decode, and enough per-device memory for each layer shard.
Choose PP
Favor capacity across nodes, sufficient concurrent microbatches, and balanced layer partitions.
Go hybrid
TP within nodes, PP across nodes, replicas across model-parallel groups. Validate topology-aware placement.
Gate dynamically
Use recent accepted length, queue pressure, and measured utility to select depth or disable speculation.
STAGE 07 COMPLETE

The systems view

Speculation converts cheap prediction into fewer target-model rounds. Parallelism converts more devices into a faster or larger target step. Neither guarantees a win: acceptance, batching, memory traffic, collectives, bubbles, and topology decide the result together.

Exit criterion: you can explain the probability correction, identify the scheduler and KV-cache changes, choose TP/PP for a concrete topology, and design a benchmark that could prove your preferred design wrong.
