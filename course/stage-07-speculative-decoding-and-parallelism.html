01 · Mental model

Two axes of parallel work

Every optimization in this stage attacks a different source of serial work. Confusing the axes leads to expensive deployments that are fast on paper and slow in production.

t→

Parallelize across future tokens

A cheap predictor proposes several continuations. The expensive target checks them in one forward pass. This is speculative decoding: improve latency without changing the model’s accepted distribution.

Σ

Parallelize one model step

Split weights or layers across accelerators. This is model parallelism: fit a large model and reduce per-step compute time, while paying communication or pipeline-bubble costs.

Keep the accounting separate. Speculation changes how many output tokens a target pass can retire. Tensor and pipeline parallelism change the cost and placement of that target pass. They can—and often should—be composed.
02 · Draft–target decoding

Predict cheaply. Verify exactly.

A small draft model q proposes a block of k tokens. The target model p scores the whole block in parallel, using the same causal mask as ordinary decoding.

One verification passk = 4
The→ kernellaunchwasslow →is

The target accepts the shared prefix (“kernel launch”), rejects at “was,” samples a corrected token (“is”), and discards all draft tokens after the first rejection.

The exact stochastic algorithm

For proposed token xᵢ, accept with probability:

a(xᵢ) = min(1, p(xᵢ | prefix) / q(xᵢ | prefix))

If rejected, sample the replacement from the residual distribution:

p′(x) = normalize(max(0, p(x) − q(x)))

This correction matters. Naively “keeping draft tokens when they look likely” biases generation. With acceptance/rejection and residual sampling, the emitted sequence has the target model’s distribution—not an approximation to it. For greedy decoding, the simpler rule is exact: accept each draft token while it equals the target argmax, then emit the target’s first disagreement.

Trace the verifierStep 1 / 4

When does it win?

Let α be the probability that each proposed token is accepted, approximated as independent for intuition. With draft length k, the expected accepted prefix is:

E[accepted] = Σᵢ₌₁ᵏ αⁱ  =  α(1 − αᵏ)/(1 − α)

The target can also contribute one fresh token after the accepted prefix, so one target verification retires roughly 1 + E[accepted] output tokens. But speedup is not that number: draft cost, target verification cost, KV-cache writes, sampling, and synchronization all remain.

Operational rule: Optimize accepted tokens per unit wall time, not acceptance rate alone. A larger draft may raise α and still lose because generating its proposals costs too much.

03 · Medusa-style heads

04 · Model parallelism

Split every layer, or split the layers?

Tensor parallelism (TP) partitions operations inside each transformer layer. Pipeline parallelism (PP) assigns consecutive layer ranges to different stages. The topology determines the communication pattern.

TENSOR PARALLEL

All devices, every layer

Shard attention heads and MLP dimensions. Each GPU computes a slice, then collectives combine partial results.

Tensor parallelism: communication is on the critical path

For a row-parallel linear layer, each rank produces a partial output and an all-reduce sums the slices. For a column-parallel layer, each rank owns output channels; a later operator may consume those shards directly or require an all-gather. A transformer block is arranged to minimize unnecessary gathers, but some collectives remain unavoidable.

TTP-step ≈ Tcompute/n + Tcollective(bytes, topology, n)

TP shines within a node connected by high-bandwidth fabrics. Across slower inter-node networking, collective latency and bandwidth can erase the compute savings—especially for low-batch decode where matrix multiplications are already memory-bound.

Pipeline parallelism: throughput trades against bubbles

With p pipeline stages and m equally sized microbatches, an idealized inference pipeline needs m + p − 1 stage-times. Utilization is:

pipeline utilization ≈ m / (m + p − 1)

At p = 4, a single microbatch uses only 25% of ideal stage capacity; 16 microbatches raise the idealized utilization to 84%. Continuous batching helps fill stages, but decode dependencies and variable completion lengths complicate scheduling.

05 · System composition

A topology is a product decision

Fast intra-node collectives keep TP local; only the hidden state crosses nodes at the PP boundary. A second 8-GPU replica can add data-parallel serving capacity.

Four interactions to reason about

  1. Verification changes tensor shapes.
    A speculative verification pass processes multiple sequence positions. Kernels may become more compute-efficient, but activation memory and attention work grow.
  2. Acceptance varies per sequence.
    In a batch, each request may accept a different prefix length. The scheduler must compact or re-bucket sequences to avoid idle lanes.
  3. KV-cache ownership follows the target.
    Accepted positions commit to the target cache; rejected speculative state must not leak into later attention. With PP, each stage owns cache for its layer range.
  4. Tail latency can hide behind averages.
    A high mean acceptance rate does not guarantee stable p99. Prompts, domains, sampling parameters, and tool-call tokens can create low-acceptance cohorts.

for mode in [baseline, speculative_k4, speculative_k8]:
    warmup(mode, requests=50)
    results = replay(

        arrival_trace=trace,
        prompts=prompt_corpus,

    report(
        throughput=results.output_tokens / results.wall_time,
        ttft=pctl(results.time_to_first_token, [50, 95, 99]),

Benchmark invariant: Compare output quality and token distributions too. A faster implementation that silently changes sampling semantics, truncates candidates, or uses a different tokenizer is not the same system.
07 · Knowledge check

Defend the design

Choose an answer, then read the explanation. A production design review should demand the same reasoning.

1. Why does correct speculative sampling preserve the target distribution?

The draft only proposes. The acceptance ratio and residual distribution ensure the final sample is distributed according to p.

2. Which metric best captures speculative decoding’s useful work?

Acceptance alone ignores draft and verification costs. End-to-end accepted tokens per wall time captures the trade.

3. You have four GPUs on one fast-interconnect node and strict per-token latency. What is the first topology to benchmark?

TP can reduce each layer’s compute time when fast links make collectives affordable. PP with one microbatch has a large bubble.

4. Why can pipeline parallelism perform poorly for a single request?

Without enough microbatches, the pipeline cannot overlap stages. TP—not PP—is the strategy characterized by frequent collectives inside layers.

5. What is the hidden cost of adding more Medusa candidate branches?

Candidate trees are bounded because wider trees consume activation memory and verification compute even though the extra heads are small.
