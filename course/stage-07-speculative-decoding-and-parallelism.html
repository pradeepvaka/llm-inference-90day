01 — THE DECODE LOOP

Draft cheaply. Verify broadly. Correct exactly.

Autoregressive decoding normally spends one target-model pass per output token. Speculative decoding changes the unit of work: a cheap model proposes K tokens, then one target pass scores the whole proposed continuation in parallel.

Draft

A small model samples x₁…xᴷ autoregressively from proposal distribution q. It must share the target tokenizer and vocabulary.

Verify

The target evaluates every proposed prefix in one teacher-forced pass, producing target distributions p₁…pᴷ.

Repair

Accept a prefix. At the first rejection, sample from the positive residual (p−q)₊; discard the rest and repeat.

“Lossless” means distribution-preserving—not token-for-token identical across unrelated random seeds.

With the rejection correction, each emitted token follows the target distribution. Greedy speculative decoding is simpler: accept exact target argmax matches, then emit the target’s mismatch token.

The correction term is the crucial detail. “Check whether the target likes the token” is not enough for sampling: a heuristic threshold can bias the output distribution. The draft helps only by proposing; the target still owns the distribution.

02 — WORKED NUMERIC MATH

Acceptance turns into speed only when draft cost stays small.

Use this compact model for first-pass sizing. Let α be average per-token acceptance, K the draft length, and c the cost of one draft step relative to one target verification pass.

E[tokens / target pass] = 1 + α + α² + … + αᴷ = (1 − αᴷ⁺¹)/(1 − α)
modeled speedup = E[tokens] / (1 + Kc)
EXAMPLE — α = 0.80, K = 4, c = 0.05independent, constant-α approximation
Accepted draft tokensα + α² + α³ + α⁴ = 0.8 + 0.64 + 0.512 + 0.4096 = 2.3616
Tokens emitted1 + 2.3616 = 3.3616. The extra 1 is the correction token—or the bonus target token when every draft is accepted.
Relative work1 target verification + 4 × 0.05 draft cost = 1.20
Idealized speedup3.3616 / 1.20 = 2.80×

Where the model overstates reality

Verifier cost grows with K, scheduling adds gaps, KV-cache writes are not free, acceptance is position-dependent, and batching can erase the low-utilization slack speculation hoped to exploit.

What to measure instead

Distribution of accepted-prefix length, draft and verify latency separately, inter-token latency (ITL), goodput at a fixed SLO, wasted draft tokens, and tail latency under real concurrency.

03 — MEDUSA

Replace the second model with future-token heads.

Medusa attaches several lightweight decoding heads to the target backbone. Head 1 predicts the next token, head 2 predicts one position farther, and so on. Top candidates form a tree that the backbone verifies with a tree attention mask.

Tree attention

Flatten tree nodes into one verification sequence, but mask attention so a node sees the original prefix plus only its ancestors. Siblings cannot leak information into one another. Position IDs reflect branch depth, not the flattened storage index.

Operational trade

No separate draft model means simpler memory ownership and deployment. The price is training or fine-tuning heads for each backbone, plus a verification kernel and cache layout that understand tree structure.

04 — DEVICE PARALLELISM

Tensor parallelism shortens a layer. Pipeline parallelism divides the stack.

Both make a model fit, but they place communication at very different points in the decode critical path. Choose from topology and latency objectives—not from device count alone.

06 — HANDS-ON LABS

Build the intuition in executable code.

The first lab needs only Python 3. The second adds PyTorch and can run on CPU; it demonstrates partition semantics rather than GPU speed.

Lab 1 · Simulate speculative roundsPYTHON 3 · ~20 MIN · NO PACKAGES
  1. Save as spec_math.py.
  2. Run python spec_math.py.
  3. Compare Monte Carlo output with the closed form. Then sweep K and notice when draft cost reverses the gain.
spec_math.py
import random

def closed_form(alpha, k, draft_cost):
    emitted = sum(alpha ** i for i in range(k + 1))
    speedup = emitted / (1.0 + k * draft_cost)
    return emitted, speedup

def simulate(alpha, k, rounds=200_000, seed=7):
    rng = random.Random(seed)
    emitted = 0
    accepted = 0
    for _ in range(rounds):
        prefix = 0
        for _ in range(k):
            if rng.random() < alpha:
                prefix += 1
            else:
                break
        accepted += prefix
        emitted += prefix + 1  # correction or bonus token
    return emitted / rounds, accepted / rounds

alpha, draft_cost = 0.80, 0.05
for k in range(1, 13):
    theory_tokens, speedup = closed_form(alpha, k, draft_cost)
    sim_tokens, sim_accept = simulate(alpha, k)
    print(f"K={k:2d} theory={theory_tokens:.3f} "
          f"sim={sim_tokens:.3f} accepted={sim_accept:.3f} "
          f"speedup={speedup:.3f}x")
→
Expected observation

At α=0.80 and c=0.05, the simple model peaks at a finite K: geometric acceptance gains flatten while draft cost continues to grow linearly.

Lab 2 · See TP and PP partition axesPYTORCH · ~35 MIN · CPU-SAFE
  1. Install PyTorch if needed: python -m pip install torch.
  2. Save as parallel_axes.py and run it.
  3. Verify that concatenating column-parallel shards reconstructs the dense output, while pipeline stages compose sequentially.
parallel_axes.py
import torch

torch.manual_seed(0)
x = torch.randn(2, 8)
W = torch.randn(8, 12)  # dense projection

dense = x @ W

# Tensor parallel: split output columns across 2 ranks.
W0, W1 = W.chunk(2, dim=1)
y0, y1 = x @ W0, x @ W1
reconstructed = torch.cat([y0, y1], dim=1)
print("TP max error:", (dense - reconstructed).abs().max().item())

# Pipeline parallel: consecutive transformations on stages.
W_stage0 = torch.randn(8, 16)
W_stage1 = torch.randn(16, 12)
h = torch.relu(x @ W_stage0)       # GPU/rank 0
out = h @ W_stage1                 # send h, GPU/rank 1
print("PP boundary activation:", tuple(h.shape))
print("PP final output:", tuple(out.shape))

assert torch.allclose(dense, reconstructed)
assert out.shape == (2, 12)

Stretch: model communication rather than hiding it

collective estimate (append to Lab 2)
def ring_allreduce_ms(payload_bytes, ranks, bandwidth_GBps, latency_us):
    # Simplified ring: 2(N-1)/N payload + 2(N-1) latency steps.
    transfer_s = 2 * (ranks - 1) / ranks * payload_bytes / (bandwidth_GBps * 1e9)
    latency_s = 2 * (ranks - 1) * latency_us * 1e-6
    return 1e3 * (transfer_s + latency_s)

B, S, H, bytes_per_elem = 8, 1, 8192, 2
payload = B * S * H * bytes_per_elem
for n in (2, 4, 8):
    ms = ring_allreduce_ms(payload, n, bandwidth_GBps=200, latency_us=3)
    print(f"TP={n}: one modeled collective = {ms:.4f} ms")

07 — KNOWLEDGE CHECK

Can you defend the design?

Answer aloud first. Open each item only after committing to an explanation.

Because proposal frequency still follows q. A token proposed too often by q would be overrepresented unless acceptance is scaled by min(1, p/q), with rejected mass repaired from the normalized positive residual (p−q)₊.
1 + 0.5 + 0.25 + 0.125 = 1.875 tokens. This includes the correction or bonus target token.
At high batch, the target may already use compute efficiently. Verifying K positions, running the draft, scheduling both models, and writing speculative KV entries consume capacity. Lower latency at low load does not guarantee higher goodput at a fixed tail-latency SLO.
Tensor parallelism. Its collectives occur inside nearly every transformer layer and sit directly on the token critical path. Pipeline parallelism transfers activations only at stage boundaries, so it is generally more tolerant of slower cross-node links.
m/(m+p−1) = 8/(8+4−1) = 8/11 ≈ 72.7%. Real inference may differ because request lengths, continuous batching, and token dependencies break the clean balanced model.
Each candidate node may attend to the original prefix and its own ancestors only. It must not see sibling branches. Position IDs must correspond to branch depth, or verification no longer matches independent candidate continuations.
