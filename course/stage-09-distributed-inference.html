01 / 08

Start with the communication path

A deployment scales only when useful compute grows faster than synchronization and state movement. Every partition introduces a collective, a transfer, or a bubble.

Weights

What must fit?

Parameters, optimizer-free serving buffers, CUDA graphs, and runtime workspaces. Tensor and pipeline parallelism divide this footprint; replicas multiply it.

KV cache

What keeps growing?

Per-request state scales with active tokens, layers, KV heads, and precision. In long-context serving, KV capacity—not weights—often limits concurrency.

Activations

What must move?

Tensor parallelism exchanges partial activations every layer. Pipeline parallelism moves boundary activations. Expert parallelism dispatches tokens all-to-all.

The governing questionFor each byte crossing a link, ask: is it on the latency-critical path, how often does it move, and can its transfer overlap useful compute?

Latency has two regimes

Prefill processes many prompt tokens in parallel and is compute-heavy. Decode processes one step at a time, repeatedly reading weights and KV state; it is usually memory-bandwidth and synchronization sensitive.

The scale-out tax

Tstep ≈ max(Tcompute, Tmemory, Tcomm) + Tsync

Adding GPUs helps only if the reduced compute term outweighs communication and synchronization overhead.

Inside a node, accelerator links behave like a tightly coupled fabric. Across nodes, the network is farther away and more contended. Your topology should respect that boundary.

03 / 08

Parallelism is not one knob

Each strategy shards a different object and pays with a different communication primitive. Hybrid serving composes them.

DP

Data parallel

Replicate the model; route independent requests to each replica.

  • Shards: request stream
  • Comm: none per forward pass
  • Win: throughput and failure isolation
  • Cost: full weights per replica
Use first when one replica fits.
TP

Tensor parallel

Split matrix operations across devices inside each layer.

  • Shards: tensor dimensions
  • Comm: all-reduce / all-gather
  • Win: lower per-device weight footprint
  • Cost: frequent synchronized traffic
Keep on the fastest fabric.
PP

Pipeline parallel

Place consecutive layer ranges on different stages.

  • Shards: model depth
  • Comm: stage-boundary activations
  • Win: scale past one node
  • Cost: bubbles and uneven stages
Batching amortizes the bubble.
EP

Expert parallel

Distribute MoE experts; route tokens to their owners.

  • Shards: expert modules
  • Comm: all-to-all token dispatch
  • Win: sparse parameter scale
  • Cost: load imbalance and hotspots
Balance routing, not just FLOPs.
Composition example

TP 8 × PP 2 × DP 4

This occupies 64 GPUs: eight-way tensor groups, two pipeline stages per replica, and four serving replicas. A request uses 16 GPUs; four requests can progress on independent replicas.

Sanity check

World size equation

N = TP × PP × DP
(+ EP as an axis or replacement inside the layout)

Frameworks differ in how EP overlaps or nests with TP/DP, so inspect the actual process groups—not just the launch flags.

Disaggregate prefill and decode

Split heterogeneous work into specialized pools, then transfer the KV state once. The architecture gains independent scaling—and inherits a placement problem.

Break-even condition

gain from specialization > KV transfer + queueing + coordination

Disaggregation is compelling when prompt and output mixes vary enough that one shared scheduler causes interference, and when KV transfer is predictable on a dedicated path.

What the router must know

  • Predicted prefill work from prompt length and model shape
  • Decode occupancy and KV capacity at candidate workers
  • Topology distance and current transfer pressure
  • SLO class: time-to-first-token versus inter-token latency

Reserve before transfer

Do not finish prefill and then discover no decode slot exists. Admission control should reserve destination capacity or define a bounded spill path.

Stream or chunk KV

Avoid a monolithic handoff when the runtime supports layer-wise or chunk-wise movement. Overlap transfer with remaining prefill work.

Backpressure at ingress

Once decode is saturated, admitting more prefills only creates expensive state that cannot advance. Reject, delay, or downgrade before work is sunk.

MoE: sparse compute, dense coordination

A router selects a small number of experts per token. Compute stays sparse, but token dispatch creates an all-to-all whose imbalance governs tail latency.

Routing flow

Score

The gate computes expert affinities for each token.

Dispatch

Top-k assignments are grouped and exchanged to expert owners.

Execute

Each expert processes its token slice, subject to capacity.

Combine

Outputs return to original token owners and are weighted.

Failure mode: the hot expert

Average load can look healthy while one expert receives a burst. That rank stalls the entire collective; all other ranks wait at the synchronization boundary.

capacity/expert = ⌈tokens × top-k × factor ÷ experts⌉

Capacity factor buys headroom but spends memory and compute. Overflow must be handled explicitly: drop, reroute, or queue—with quality and latency consequences.

Four common distributed failures

01
Rank desynchronization

A timeout is often a downstream symptom. Find the first rank that stopped entering collectives.

02
Topology mismatch

Logical process groups span slow links because rank placement ignored physical locality.

03
Queue coupling

One workload class consumes capacity needed by another, so head-of-line blocking becomes an SLO outage.

04
Silent imbalance

Average utilization is high but useful work is gated by one pipeline stage or expert rank.

07 / 08

Lab: prove the network ceiling

Run a small collective benchmark, compare predicted transfer time with measured latency, and write a topology recommendation. The goal is explanation, not a pretty number.

Choose two process layouts

Layout A keeps the collective within one node. Layout B spans two nodes. Use the same world size and message sizes if the hardware permits; otherwise record the difference explicitly.

Sweep payload size

Measure small payloads to expose launch and network latency, then larger payloads to approach bandwidth limits. Warm up before recording samples.

Predict, measure, explain

Estimate a lower bound from bytes ÷ link bandwidth. The gap to measured time contains protocol overhead, topology effects, contention, and synchronization skew.

Translate to serving

Estimate how often the target model invokes that collective per generated token. Convert microbenchmark time into an approximate per-token communication budget.

Minimal PyTorch probe

# launched under torchrun import os, time, torch import torch.distributed as dist dist.init_process_group("nccl") rank = dist.get_rank() torch.cuda.set_device(int(os.environ["LOCAL_RANK"])) for mib in [1, 4, 16, 64, 256]: n = mib * 1024 * 1024 // 2 # fp16 elements x = torch.ones(n, device="cuda", dtype=torch.float16) for _ in range(10): dist.all_reduce(x) torch.cuda.synchronize() t0 = time.perf_counter() for _ in range(50): dist.all_reduce(x) torch.cuda.synchronize() ms = (time.perf_counter() - t0) * 1000 / 50 if rank == 0: print(f"{mib:>3} MiB {ms:8.3f} ms") dist.destroy_process_group()

Launch pattern

# node 0 MASTER_ADDR=<node0-ip> MASTER_PORT=29500 \ torchrun --nnodes=2 --nproc-per-node=8 \ --node-rank=0 probe.py # node 1: same command, but --node-rank=1

08 / 08

Knowledge check

Choose the best answer. Explanations appear immediately; nothing is saved.

1. A model fits on one 8-GPU node. You need 4× throughput for independent requests. What is the cleanest first move?

Data parallelism scales independent request throughput without adding per-token collectives, provided each replica fits.

2. In a disaggregated design, prefill completes quickly but TTFT spikes when decode is busy. What is missing?

Producing KV state without a destination creates stranded work. Reserve decode capacity before or during prefill and throttle admission.

3. Average expert utilization is balanced, yet p99 latency spikes. What should you inspect next?

Short correlated bursts at one layer or rank can stall all-to-all collectives while global averages remain healthy.

4. Why keep tensor-parallel groups within an NVLink island?

TP communicates inside many layers. Fast, low-latency local links reduce this recurring critical-path cost; synchronization still exists.
